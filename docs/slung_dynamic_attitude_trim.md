# 运动参考下的构型补偿

动态构型补偿已接入 `reference_cascade`，可在圆周、八字、圆锥或固定目标下使用。
它根据负载相对瞬时期望姿态的误差，缓慢更新三机参考，保留负载目标姿态。
目前是可切换的实验功能，省略动态参数时兼容旧模式，当前实飞配置已选择动态模式。
已有离线结果只有小幅改善，尚不能证明解决最新实飞中的
负 pitch 大偏差、观测导数尖峰和初始构型未收敛。

## 参数

在 `config/slung_payload.yaml` 设置：

```yaml
slung_payload:
  transport_attitude_trim_enabled: true
  transport_attitude_trim_dynamic_enabled: true
  transport_attitude_trim_during_lift_enabled: true
  transport_attitude_trim_feedback_max_rate_rps: 0.50
  transport_attitude_trim_feedback_pose_jump_deg: 1.0
  transport_attitude_trim_feedback_recovery_s: 0.50
  transport_attitude_trim_gain_per_s: [0.05, 0.10, 0.01]
  transport_attitude_trim_limit_m: 0.010
  transport_attitude_trim_rate_limit_mps: 0.0015
  transport_attitude_trim_acceleration_limit_mps2: 0.002
  transport_attitude_trim_interval_s: 1.0
```

动态开关设为 `true` 后选择 `SlungDynamicAttitudeReferenceTrim`；设为 `false` 保留原静态
模式及其运动冻结规则。总开关关闭时两种构型补偿均不执行。飞机位置 PID 的积分是独立
环节；差分力积分仍沿用原门控，不因动态构型开关而放开运动学习。
当前用户任务为圆锥半角 15°、两圈，任务选择以实际 YAML 为准，没有改动机载增益。

`transport_attitude_trim_during_lift_enabled` 是独立的提前更新开关，只有动态模式才生效。
设为 `true` 时，接管后先等待张力渐增完成并要求所有飞机协同混合系数达到1，
然后允许在抬升和姿态参考尚未结束时按瞬时完整目标更新；当前最早h5，覆盖原h5–17等待段。
前5秒仍不积累构型补偿，第一段位置/速度/加速度从零连续启动。
设为`false`则恢复参考建立结束h17后才更新；省略该参数也兼容旧值`false`。
单机位置I和差分力积分仍保留原等待条件，正分配张力、EKF、反馈质量及输出限幅门控不变。
提前更新可能积累正常跟踪滞后造成的暂态偏置，须检查过冲；并不代表已修复观测尖峰或
能保证实飞在某个固定秒数内调平。

## 参考生成与异常门控

每个学习段开始时，用完整期望旋转矩阵计算姿态误差，将其转换为世界系位置增量。
已有偏置直接存为世界系端点，圆周/八字不再额外按 yaw 旋转该偏置。统一投影和步长缩放
保证三机偏置之和为零，以及每机偏置自身的范数、速度、加速度预算。
每段五次曲线在端点速度、加速度归零，只有上一段完成后才开始新段；输出保持 C2。
限幅只约束学习偏置，名义轨迹和降落残差桥仍使用各自的边界。

学习仍要求原有位置/EKF/负载反馈健康、正的分配张力、上一主机输出未限幅，且未进入
降落或故障。新动态门控额外检查负载角速度范数、源时间顺序和相邻原始姿态步长。
姿态步长预算包含固定 1° 加源时间间隔允许的转动量；角速率等异常之后需恢复 0.5 s。
缓存保持暂停新学习，已有段继续走完；降落沿已有完整 PVA 残差桥衔接。

这些门控保护的是补偿更新，不会替换负载 PD 环已经使用的观测角速度，也没有修复原
观测器的时间戳或导数尖峰。更大的姿态增益、补偿上限仍需单变量验证。

`transport_attitude_trim_integral_*` 在动态模式下是世界系小角增量的累计诊断，不能用它
和当前目标姿态重建三机参考；实际输出以 `transport_attitude_trim_position/velocity/acceleration_*`
为准。其推导和旧模式对照见 [公式文档第 9 节](slung_controller_formulas.md#9-姿态到构型的慢修正与下降衔接)。

## 2026-10-23 离线对照

以下使用相同控制增益、Graefe 电机物理和 70 Hz 主机控制；所有列出的完整任务均通过
原仿真完成判据，并完成负载落地、三机降落停推。没有放宽已有误差/安全判据。

| 场景 | 静态冻结：完整姿态误差 RMS | 动态构型：完整姿态误差 RMS | 质心位置误差 RMS，静态 → 动态 |
|---|---:|---:|---:|
| 15° 圆锥，两圈各30 s | 2.191° | 2.179° | 7.23 → 7.40 mm |
| 15° 圆锥，CF3 物理绳长增加10 mm | 2.184° | 2.170° | 7.26 → 7.43 mm |
| 当前圆周任务，两圈 | 6.753° | 6.470° | 6.80 → 8.88 mm |

圆锥指标仅统计两圈扫描；圆周指标统计圆周运动期间。完整姿态误差包含 yaw，不能与
单独 pitch 或 +Z 轴方向误差互换。圆周与圆锥是不同任务，不能跨行直接比较控制能力。
动态补偿并未消除所有偏差，且位置误差略增；这是可用的受限对照，不是大幅改善的证明。

单绳误差场景中，动态三机偏置最大约 2.37 mm、速度约0.650 mm/s、加速度约2.00 mm/s²，
均在原预算内，偏置零和。最小机间距约0.466 m，带符号请求张力保持正值。
第二圈的姿态误差仍略大于第一圈，不能宣称重复扫描会单调收敛。

另测试了 CF3 物理推力效率降低5%和10%的场景：静态、动态两组都在接管前起吊超时，
未进入新补偿阶段。这些失败结果予以保留，不能用于判断动态构型的效果。

新增测试覆盖变化目标下精确跟踪不学习、偏差学习方向、完整 PVA 导数、全段限幅和零和、
同tick幂等、重复/乱序源时刻、姿态突跳、角速率异常、恢复门控、缓存及中途降落衔接。
主机完整回归为1151项通过、1项缺少MuJoCo跳过；实际MuJoCo对照在独立udaan环境中执行。
系统 Python 3.8 可导入/实例化动态类，实飞参数通过离线 XML-RPC 序列化检查。

本地结果目录：`ros_ws/src/crazyswarm/scripts/ctbr_logs/dynamic_trim_20261023/`，包含
`nominal_static`、`nominal_dynamic`、`circle_static`、`circle_dynamic`、`unequal_link` 和
不可评价的 `motor90`/`motor95`。每次保存输入参数快照、控制 CSV、物理 trace 和 summary；
单绳对照另有 `comparison.json/png/svg`。运行数据由 Git 忽略，文档可独立阅读。

## 下一步

原实飞前后机已有数厘米构型误差，而此功能保持每机1 cm偏置预算和很低的更新速度，
不能期待它在起扫前3秒消除这些误差。优先修观测导数质量、增加真实收敛启动条件并
处理实际循环掉频；再对动态构型增益和学习速率做逐项验证。
30° 参考的小张力/急速构型问题仍需参考可行性约束，动态trim不代替该约束。
