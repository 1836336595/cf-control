# Mellinger 仿真与实飞预抬不一致的纠正

用户指出：实飞可以完成负载预抬，明显失稳发生在切换阶段。实飞 `multi_ctbr_20261015_221859.csv` 确认，控制时间 49.27365 秒进入 TAUT_RAMP 时负载中心高度为 0.67649 m，底面间隙为 0.63950 m。

此前“固件原始大增益使 Mellinger 在仿真中无法抬升”的因果结论不成立。新增执行器模型存在以下错误，均已通过先失败、后通过的回归测试确认修复：

1. **pitch 速率反馈符号相反。** 固件 `ew.y=-wire_pitch-(-gyro.y)`，在原 Mellinger 桥接 pitch_sign=+1 下等于 `actual_q-commanded_q`；旧模型使用相反符号，经混控又反号后成为错误方向的响应。
2. **姿态误差少一倍。** 固件快速公式使用完整 skew 的 vee。单轴滚转 θ 时为 `2*sin(θ)`；旧模型使用主机几何控制器的 `0.5*vee`，错误减半。
3. **yaw 目标持续累积。** 固件每个内环 tick 用 `current_yaw + commanded_yaw_rate*dt` 重新计算，旧模型却累积上一时刻的 yaw 目标。
4. **500 Hz 时钟没有落实。** 物理积分在主机 tick 或观测时刻会拆出小于 2 ms 的子步，旧模型每个子步都执行一次完整 2 ms 的积分/微分。修复后只在 500 Hz 截止时间采样控制并在其间保持 PWM，MuJoCo 也按该截止时间分割积分。

另外，回放开始时现在通过 `reset_actuators()` 一起初始化电机推力状态；此前只修改了 collective 的诊断缓存，电机状态仍从零开始。

之前把机载 Mellinger 的 `[70000,70000,60000]` 改成主机风格 `[12,12,6]` 并称为“归一化稳定候选”也不正确。两者职责和输出单位不同；当前模型的 Mellinger 增益最终输出 PWM，不能凭状态采用 rad/s 就替换为主机增益。已在仿真参数中恢复固件源码增益，保留用户选择的 `onboard_controller: pid` 不变。本次验证通过运行覆盖选用了 Mellinger，没有改动实飞 launch。

## 修正后回放

输出目录：`mellinger_corrected_20261016`。配置：70 Hz 主机控制、100 Hz 位姿、20 ms 位姿延迟、10 ms 指令延迟、500 Hz Mellinger、接管后目标观察窗口 60 秒。使用机载姿态增益 `[70000,70000,60000]`、速率增益 `[20000,20000,12000]`、速率误差微分增益 200。

- 约 **28.9143 秒**完成预抬并进入 `tension_ramp`。
- 接管后的最低负载间隙约 **0.3312 m**，说明负载已经离地。
- 随后进入 `height_correction`；约 **36.9143 秒**触发实际机间距保护。
- 相位顺序为 `takeup → tension_ramp → height_correction → emergency_landing`。
- 本轮没有完成 60 秒窗口，`success=false`，不能作为稳定或实飞就绪的结论。

这是“已能预抬、问题发生在接管后”的定性一致性改善，不等于已经复现真实 4–5 Hz 振荡、真实载荷接管高度或辨识了所有执行器参数。机载实际固件/参数、电机推力映射和估计器链仍需核实；当前回放的车辆 EKF 速度/加速度仍为延迟理想状态，未模拟完整固件 EKF。
